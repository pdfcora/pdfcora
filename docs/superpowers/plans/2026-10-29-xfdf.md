# XFDF export and import — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `exportXfdf` and `importXfdf` on the document in the Web/Node, iOS, Android and Java SDKs, producing byte-identical XFDF and identical import reports for one shared conformance case.

**Architecture:** One hand-written conformance case (`conformance/xfdf/`) fixes the exact output. Each platform adds a small XML reader/writer, internal engine readers/writers for the annotation entries the public model lacks, and the two document methods; the public annotation and form models do not change.

**Tech Stack:** TypeScript (Node test runner), Swift (XCTest, PDFium C API), Kotlin + JNI (instrumented tests), Java 17 + JNI (JUnit 5), Node for the fixture generator.

**Spec:** `docs/superpowers/specs/2026-10-29-xfdf-design.md`

## Global Constraints

- No XML library dependency beyond the platform's own. Reject any input containing `<!DOCTYPE` or an entity other than `&amp; &lt; &gt; &quot; &apos;` and numeric `&#…;`. Input limit: 10 MiB (10485760 bytes of UTF-8).
- Errors: malformed XML, root not `xfdf`, input over the limit, closed document → the existing `invalidOperation` (Java `INVALID_OPERATION`). Nothing is written when an error is raised.
- Report: `fieldsSet`, `annotationsAdded`, `skipped: [{ element, page?, reason }]`; reasons exactly `unsupportedType`, `unknownField`, `readOnlyField`, `invalidValue`, `pageOutOfRange`, `missingAttribute`, `writeFailed`.
- API names: Web `exportXfdf(): Promise<string>`, `importXfdf(xml: string): Promise<PdfXfdfReport>`; iOS `exportXFDF() async throws -> String`, `importXFDF(_:) async throws -> PdfXfdfReport`; Android `suspend fun exportXfdf(): String`, `suspend fun importXfdf(xml: String): PdfXfdfReport`; Java `String exportXfdf()`, `PdfXfdfReport importXfdf(String xml)`.
- Public annotation/form models unchanged; all new engine access is internal.
- **Canonical export format** (every platform must produce exactly this):
  - `<?xml version="1.0" encoding="UTF-8"?>\n<xfdf xmlns="http://ns.adobe.com/xfdf/" xml:space="preserve">\n`, children indented by 2 spaces per level, `\n` line ends, ends with `</xfdf>\n`.
  - `<fields>` first, then `<annots>`; a section with no children is omitted.
  - Fields in order of their first widget (page, then annotation index); widgets sharing a full name are one field; `a.b` → `<field name="a">` containing `<field name="b">`. Value elements: `<value>…</value>`, one per selected option for list boxes.
  - Annotations ordered by page, then annotation index. Element names: `highlight underline strikeout squiggly ink text square circle line freetext stamp fileattachment`. Widgets, links and `unknown` are not exported.
  - Attribute order: `page rect color opacity flags name title date creationdate` then type-specific `coords` | `width` | `icon` | `start end`. Omit an attribute whose value is absent; omit `opacity` when 1.
  - Numbers: at most 4 decimals, trailing zeros and a trailing `.` removed, `-0` written `0`.
  - `rect` = `left,bottom,right,top`; `coords` = the quad points in `/QuadPoints` order, comma-joined; ink `<inklist><gesture>x,y;x,y</gesture>…</inklist>`; `start`/`end` = `x,y`.
  - `color` = `#RRGGBB` uppercase hex; `flags` = names in bit order `invisible,hidden,print,nozoom,norotate,noview,readonly,locked,togglenoview,lockedcontents`, comma-joined without spaces.
  - Children of an annotation: type-specific first (`inklist`), then `<contents>`, then `<defaultappearance>` (freetext).
  - Escaping: attributes `& < > " '`; text `& < >`.

## Review Focus

1. Text with `&`, `<`, quotes and non-ASCII (e.g. `Zoë & "Co" <ok>`) in contents, author and field values → round-trips exactly. Test: `exportEscapesAndKeepsUnicode` (each export task, against the fixture).
2. An XFDF with `<!DOCTYPE` declaring an external entity → `invalidOperation`, document unchanged, no file or network access. Test: `rejectsDoctype` (each import task).
3. Importing the same XFDF twice → annotations are added twice (no merging), fields keep the last value; nothing crashes. Test: `importingTwiceAddsTwice` (each import task).
4. A field name that matches several widgets of different kinds, or a radio value matching no widget → `invalidValue`, other fields still applied. Test: covered by `import.xfdf` rows checked in `expected-import.json`.
5. A document with no fields and no annotations → export is the root element only, with no sections. Test: `exportsEmptyDocument` (each export task, on `conformance/corpus/hello_world.pdf`).

### Task 1: Shared conformance case

**Interfaces:**

`source.pdf`, two pages:
- Fields: text `customer.name` (value `Zoë & "Co" <ok>`), check box `agree` (export `Yes`, on), combo `country` (options `Austria, Germany, Switzerland`, value `Germany`), radio group `size` (widgets `S`, `M`, `L`, `M` on), text `ref` with one widget on page 0 and one on page 1 (value `R-17`), a push button `submit`.
- Annotations, each with `/C`, `/F 4` (print), `/NM`, `/T`, `/M`, `/CreationDate`, `/Contents`: highlight, underline, strikeout, squiggly (each one quad), ink (two strokes, `/BS /W 2`), text note (`/Name /Comment`), square, circle, line (`/L`), freetext (`/DA`), stamp; one link (must not be exported); one highlight with `/CA 0.5`.
- `source-blank.pdf`: same fields with empty/off values, no annotations.

`import.xfdf`: values for all fields of `source-blank.pdf` (radio `L`, list of one combo option), plus: `customer.name` given as nested fields; one each of ink, text, highlight, underline, strikeout (with title/name/date/creationdate/color/opacity/contents); one each of square, line, freetext (→ `unsupportedType`); a field `nope` (→ `unknownField`); radio value `XL` in a second `<field name="size">` (→ `invalidValue`); a highlight on `page="9"` (→ `pageOutOfRange`); an ink with no `<inklist>` (→ `missingAttribute`).
