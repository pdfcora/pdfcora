# Alt Text Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** List figures without alternate text in tagged PDFs, propose descriptions or decorative marking, and write what a person confirms so the document passes PDF/UA-1.

**Architecture:** The core gains a structure-tree read (`page.structure()`, `document.isTagged()`) over PDFium and a figure write (`document.updateFigures`) that re-marks decorative content in PDFium and appends `/Alt` and `/K` changes through the byte-level writer. `pdfiumkit-ai` finds figures, applies the decorative rule, gathers context and an image, and asks the routes. The web implementation is the reference the Swift and Kotlin ports follow.

**Tech Stack:** TypeScript, Swift 5.9, Kotlin 1.9 + JNI C++, PDFium, veraPDF 1.30.

**Spec:** `docs/superpowers/specs/2026-09-15-alt-text-design.md`

## Global Constraints

- Figure: `/S` `Figure`, no non-blank `/Alt` or `/ActualText`, with marked content on the page.
- Decorative rule: shorter side ≤ 3 pt or area ≤ 100 pt².
- Context: character centres inside the rect grown by 48 pt, whitespace collapsed, ≤ 500 chars.
- Image: longer side ≤ 512 px, scale ≤ 4, PNG.
- Proposal id: `"<pageIndex>:<ids joined by ,>"`. Notice: `Check every description before it is written.`
- Tree walk: ≤ 64 levels, each object once; element must be indirect.
- `updateFigures` gated `editing`; suggest gated `ai`.
- veraPDF: `~/.cache/verapdf/app/verapdf --flavour ua1` locally; CI installs it.
