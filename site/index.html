Why PdfiumKit

iOS, Android, the Web — and your server.

One engine and one API across all of them, so a feature behaves the same on an iPhone, an Android tablet, in the browser and in a batch job — in Swift, Kotlin, TypeScript and Java, each written the way that language’s developers expect.

Bad files don’t crash your app.

Malformed, truncated and password-protected documents come back as typed errors you can handle, not as a native crash somewhere inside the engine.

The engine behind Chrome.

Built on PDFium, pinned to a known revision, with the same public API compiled into every platform’s build.

Safe from any thread.

Every document runs on its own serial executor. Call it from anywhere — you can’t corrupt memory by using the wrong thread.

Light enough for mobile.

Web engine1.5 MB
Android arm644.77 MB

Recovers when the engine can’t.

A malformed page can stall any PDF engine. On the Web, PdfWorker runs the whole SDK in a Worker behind the same API — so your page stays responsive and a stuck render can simply be terminated.

const doc = await worker.open(bytes)
// same API as in-process
worker.terminate() // page keeps running

Features

Everything your users do with a PDF.

Viewing, searching, marking up and filling in — available today on all three platforms.

  • View & render

    Crisp pages at any size or exact pixel dimensions, with annotations and form widgets on or off.

  • Search text

    Full-text search with result rectangles, text extraction and per-character bounding boxes.

  • Annotate

    Read 15 annotation kinds. Draw ink, add notes and remove annotations — plus highlights on iOS.

  • Fill forms

    Read 8 field kinds and set text, checkboxes and choices — or place native controls right on the page.

  • Navigate

    Outlines, bookmarks and links, so readers can jump straight to what they need.

  • Attachments & metadata

    List and extract embedded files, and read document metadata and permissions.

  • Save changes

    Save in full, or incrementally to keep the original bytes and existing signatures intact.

  • Protected files

    Open password-protected documents, with a clear typed error when a password is needed.

  • Sign & verify

    Read and verify existing signatures, and sign documents as PAdES B-T with a trusted timestamp.

  • Redact for real

    Content is removed from the saved bytes, not covered with a black box that anyone can select underneath.

  • Tag for accessibility

    Read a document’s structure, write alternate text, and turn an untagged PDF into one built to PDF/UA-1. More →

  • AI where it helps

    Grounded answers, summaries, redaction and form proposals, alt text and semantic diff — on device, or through your own model. More →

  • Tools for agents

    An MCP server and WebMCP, so an agent can read a document freely and change it only through proposals a person accepts. More →

  • A viewer, included

    A component with a configurable toolbar, theme and review bar on all three platforms — or drive the state layer yourself.

  • Offline licensing

    Keys are verified offline and unlock modules per app ID or host. Without one everything still works, watermarked. More →

Developer experience

Your first render in four lines.

Async from top to bottom, idiomatic in every language, and nothing to configure before you open a file.

  • async/await on iOS, coroutines on Android, promises on the Web
  • Typed errors instead of native crashes
  • Explicit coordinates — no hidden Y-flip
Swift 
let doc  = try await PdfDocument(url: url)
let page = try await doc.page(0)
let img  = try await page.render(width: 1200)
let hits = try await page.text.search("invoice")
Kotlin 
PdfDocument.open(file).use { doc ->
    val page = doc.page(0)
    val bmp  = page.render(width = 1200)
    val hits = page.text.search("invoice")
}
TypeScript 
const doc  = await PdfDocument.open(bytes)
const page = await doc.page(0)
const img  = await page.render({ width: 1200 })
const hits = await page.text.search('invoice')

Built for real files

The files your users send are not the files you designed for.

Truncated downloads, generator bugs, decades-old scanners, files that were never valid. PdfiumKit is built so those arrive as errors you can handle rather than as a crash.

We tell you about the edge cases

A malformed page can stall PDFium’s renderer, and we cannot fix that.

It stalls inside the engine, where no cancellation can reach it. So PdfiumKit contains it instead: every document has its own executor, so a stalled one cannot take the others with it, and later calls to it fail fast with a typed error rather than queueing behind it. On the Web, PdfWorker recovers completely.

Design decisions

Thread-safe

An actor on iOS, a single-threaded dispatcher on Android, a promise chain on the Web. Misuse raises PdfError.closed instead of corrupting memory.

Typed errors

A closed set of error cases, identical on all three platforms.

Explicit coordinates

PdfRect is always PDF space; toView and toPdf convert in each direction. No hidden Y-flip.

Nothing silently dropped

Every sealed hierarchy has an unknown case, so unmodelled annotation and field types are surfaced, not lost.

Where it stands

Shipped, and what is still open.

Everything in the first list is built on all three platforms today. The second list is what we have not done — kept here rather than in a footnote.

  • Shipped

    Digital signatures

    Read and verify existing signatures, and sign as PAdES B-T with a trusted timestamp.

  • Shipped

    Redaction

    Content removed from the saved bytes, so it cannot be recovered from the file.

  • Shipped

    Text markup everywhere

    Highlight, underline and strikeout on iOS, Android and the Web.

  • Shipped

    Accessible viewer

    Document structure exposed to VoiceOver, TalkBack and screen readers, with keyboard control and text scaling.

  • Shipped

    Accessibility remediation

    Tags, reading order and alternate text for an untagged PDF, confirmed by a person before anything is written.

  • Shipped

    Bring your own model

    On-device models where the platform has one, your endpoint where it does not, patterns where neither exists.

  • Open

    Published packages

    SPM, Maven and npm artifacts, and the engine binaries as checksummed release assets. Today the SDK is built from the repository.

  • Open

    An independent accessibility audit

    Not yet commissioned, so there is no third-party conformance report to hand you.

  • Open

    Cancellable renders, wider recovery

    Cancelling inside an engine call is not possible; full recovery from a hang is Web-only.

  • Open

    Tables, OCR and encrypted writes

    Remediation turns tables into paragraphs, there is no OCR for scans, and encrypted documents can be read but not rewritten.
