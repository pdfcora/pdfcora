Features

Everything you need to open, read and change a PDF.

The same capabilities, the same types and the same error cases on all three platforms.

Rendering

Render any page to a bitmap at a scaled size or exact pixel dimensions, with annotations and form widgets on or off.

Text and search

Extract page text, search with result rectangles, and get bounding boxes for every character.

Annotations

Read 15 annotation kinds. Create ink and notes, and remove annotations. Highlight, underline and strikeout on iOS.

Form fields

Read 8 field kinds and set text, checkbox and option values. Position native controls over field rectangles with PdfViewTransform.

Document structure

Outline and bookmarks, links, metadata, permissions, and attachments — list them and extract their bytes.

Saving

Save in full, or incrementally to preserve the original bytes and any existing signatures.

Password-protected files

Open from bytes or a file, with a password when required — reported as a typed error you can prompt on.

Recoverable on the Web

PdfWorker runs the whole SDK in a Worker behind the same API — so a hung render can be terminated and your page keeps running.

One contract, three SDKs

A single expectations file defines page counts, geometry and failure modes for 18 corpus documents, and all three SDKs are tested against it. Page counts are cross-checked against poppler, so the suite isn’t grading itself.

Rendering is checked by position: a known RGB test page must place blue, green and red exactly where the reference engine does — which catches channel-order bugs pixel counting can’t.

Text is checked by exact character count plus a SHA-256 of the normalised page text. The three SDKs share an engine but have three independently written UTF-16 decoders; this is where an off-by-one would surface.

Known limit

One 1,230-byte file hangs PDFium’s renderer — so we measured the damage.

Opening it, reading text, annotations and fields all complete in about 20 ms. Only rendering hangs, inside a native call that no cancellation can interrupt. It reproduces with raw FPDF_* calls; it is engine behaviour, not a binding bug.

Each document runs on its own serial executor, so the hang is contained: with 16 simultaneous hangs on iOS and 10 on Android, other documents kept rendering and the rest of the app kept working. On the Web, PdfWorker recovers fully:

TypeScript 
const worker = new PdfWorker({ workerUrl, glueUrl, wasmUrl })
const doc  = await worker.open(bytes)
const page = await doc.page(0)
const img  = await page.render({ width: 1200 }) // same API

worker.terminate() // pending calls reject: 'cancelled'

Design

Hard to misuse, by construction.

Thread-safe

Each document owns a serial executor — an actor on iOS, a single-threaded dispatcher on Android, a promise chain on the Web. Calling from the wrong thread can’t corrupt memory; misuse raises PdfError.closed.

Typed errors

Errors are a closed set with the same cases on all three platforms. Malformed input surfaces as an error you can handle — not a native crash.

Explicit coordinates

PdfRect is always PDF space. Converting is an explicit call in each direction — toView to draw, toPdf to hit-test. No hidden Y-flip, anywhere.

Nothing silently dropped

Every sealed hierarchy carries an unknown case, so annotation and field types the SDK doesn’t model yet are surfaced rather than lost.

Planned

Where it’s heading.

None of this is available yet. It’s the direction of travel, not a commitment to dates.

  • Close the coverage gaps

    Highlight, underline and strikeout on Android and Web; a raw engine escape hatch beyond iOS.

  • Accessible viewer

    A viewer designed to conform to EN 301 549 and WCAG 2.1 AA — keyboard navigation, screen-reader semantics, reflow.

  • Accessibility remediation

    AI-proposed tags, reading order and alt text, confirmed by a person before anything is written.

  • Redaction

    Detect and remove sensitive content, with suggestions always reviewed before they’re applied.

  • Digital signatures

    Sign documents and verify existing signatures.

  • Bring your own model

    AI features that run locally or against your own endpoint, so documents never leave your infrastructure.
