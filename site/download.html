Every feature works without a licence key — rendered pages, saved files and AI output simply carry a “PDFCora trial” watermark. A key removes it and unlocks the modules it names, and it is checked offline, so nothing phones home. The Java SDK has no licensing module yet, so it neither checks a key nor watermarks.

The trial

Nothing is disabled. It is watermarked.

You can evaluate every feature, on every SDK, for as long as you like — including signing, redaction and the AI features. What you cannot do is ship the output.

What the trial marks

Rendered pages, saved files and AI output carry “PDFCora trial”. The watermark is written as an artifact, so it is never read out by a screen reader — but its font is a standard one, so a watermarked file cannot claim PDF/UA.

What the trial changes

A watermarked document is always saved in full, even when you ask for an incremental save, and signing it rewrites the file first — so signatures already in that file stop verifying. With a key, incremental saves and earlier signatures are kept.

What a key does not do

It never makes the SDK throw. PdfLicense.status tells you whether the key is valid, which modules it covers and why one was rejected, and the SDK keeps working either way.

Todo Java is not licensed yet

The JVM SDK carries no licence check and writes no watermark, so its output is unmarked whether or not you hold a key. That is a gap, not a concession — it will be brought in line before 1.0.

Licence keys

One key, the modules you need.

A key names the modules it unlocks and the app IDs and web hosts it is for. Viewing, text extraction, search, verifying signatures, the viewer and cross-platform sync need only a valid key — no module at all.

Licence modules
ModuleCovers
editingAnnotations, page operations and saving changes
formsFilling form fields and creating them, including flat form detection
signingSigning documents — reading and verifying signatures is always included
redactionRemoving content so it cannot be recovered
aiEverything in pdfcora-ai, including remediation and alt text
Before opening documents 
PdfLicense.setKey("pk1.…")
In Application.onCreate 
PdfLicense.setKey(context, "pk1.…")
Before opening documents or creating a PdfWorker 
await PdfLicense.setKey('pk1.…')

Keys are verified offline against a public key compiled into the SDK. The check deters use beyond a licence; it is not copy protection.

What is in the binary

Third-party licences, stated up front.

PDFCora ships as a binary that statically links PDFium and six bundled libraries. The combination is permissive — the one that usually causes trouble is FreeType, and it is used under the FreeType License rather than GPLv2.

Bundled third-party components
ComponentLicence
PDFium (chromium/7243)BSD-3-Clause
FreeTypeFreeType License (FTL), not GPLv2
Skia, libjpeg-turbo, libpng, zlib, libopenjpegBSD-style and zlib licences
