Agents

Let an agent work on a PDF —
without letting it loose.

One set of tools, served two ways: an MCP server for desktop agents, and WebMCP for the browser’s own agent. Reading is free. Every change is a proposal a person accepts, it can be undone, and saving never writes over the file that was opened.

Run the agent demo → See the tools

Two ways in

The same tools, wherever the agent lives.

Node

An MCP server

pdfcora-mcp speaks the Model Context Protocol over stdio, so any MCP client can start it from its own configuration. It handles many documents at once, each addressed by id, on the same @pdfcora/node engine your own server code would use — so a tool the agent calls and a job you run yourself see the same document.

Browser

WebMCP

registerWebMcpTools(session) offers the same tools to the browser’s agent for the document your page already has open. Where the browser has no WebMCP it returns nothing, so your page can say so instead of breaking.

The tools

Read freely. Change only by proposal.

Read-only tools are annotated as such, so a well-behaved client can use them without asking. The two that write are annotated destructive.

Guardrails

What stops an eager agent.

  • Proposals expire. Applying or undoing invalidates every open proposal set, because they describe a document that no longer exists. Using a stale one is an error.
  • Only accepted ids are written. The tool description says so and the server enforces it: an id outside the set fails the call rather than writing part of it.
  • Undo is always available for the last apply, from a snapshot taken before it.
  • The original file is never overwritten. save_document refuses the path it opened.
  • The agent is the model. The tools run patterns and rules; they call no model of their own unless your host configured a provider for the session.
